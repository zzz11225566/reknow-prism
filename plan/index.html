炼知 ReKnow

把知乎收藏，炼成自己的回答

炼知把用户收藏夹里的优质回答，变成可拆解、可验证、可连接、可输出的个人知识资产。 它不是第二个收藏夹，而是连接知乎内容消费、主动学习与社区创作的一条知识加工链。

01 / 评审摘要

收藏不是终点，理解与输出才是

炼知的核心命题不是“帮用户整理更多内容”，而是解决知乎社区中一个高频而长期存在的问题： 用户收藏了大量好回答，却没有把它们转化为自己的能力、表达和行动。

让知乎收藏完成一次身份转换：从沉睡的内容库存， 变成用户可以理解、验证、迁移并重新发布的个人知识资产。

炼知 ReKnow 产品使命
01

用户问题真实

收藏门槛极低、回看成本很高。用户获得的是“以后会看”的安全感， 而不是稳定、可调用的知识。

02

方法不是摘要工具

用第一性原理拆出事实、假设、推导与边界，再用 AI 抬杠检验理解， 最后回到真实场景。

03

体验形成长期动机

主题是星系、文章是行星、学会即点亮。知识进度从抽象百分比变成 可观察、可探索的个人宇宙。

04

社区价值闭环

原文、收藏、学习、回答仍在知乎生态内流转。炼知只组织用户的学习结果， 不截断内容来源与创作回流。

02 / 问题定义

“收藏吃灰”背后，缺失的是一道加工工序

看到好内容 即时获得感
→
点击收藏 安全感替代理解
→
长期不打开 结构与语境丢失
→
需要用时找不到 无法表达或迁移

缺失工序有三个：没有主动重建，缺少压力测试，也没有面向输出的知识结构。 炼知针对的不是“信息太多”，而是“信息无法变成能力”。

03 / 核心创作思路

用一条可验证的认知闭环，重写收藏的价值

产品围绕“主动重建而非被动阅读”设计。 每一步都对应一种认知动作，也都有清晰的完成标准。

  1. 01

    选料

    从知乎收藏或系统推荐中确定今天真正要解决的问题。

  2. 02

    拆解

    区分结论、事实、经验、隐含假设、推导链与适用边界。

  3. 03

    AI 开杠

    让 AI 抓住用户原话中的漏洞，用边界、反例和前提逼问理解。

  4. 04

    图谱

    把知识卡、概念、观点和关系连接成可重建的个人结构。

  5. 05

    回流

    形成回答草稿、行动方案或表达材料，再把结果带回知乎。

PRINCIPLE A

主动重建

不把“看过”当成“学会”。用户必须用自己的语言重建因果链， 才能标记为已学会。

PRINCIPLE B

AI 作为反对派

AI 不替用户写答案，而是指出模糊词、隐藏前提和失效场景， 将“看懂”变成经得起追问的理解。

PRINCIPLE C

知识可迁移

每个知识点最终都要落到真实任务、生活情境或输出目标， 避免知识只停留在笔记中。

04 / 产品结构

一个高效率工作台，一座长期生长的知识宇宙

界面一 · 收藏拆解

把阅读变成可操作的学习流程

收藏进入主题归类后，用户可以逐篇拆解、记录札记、与 AI 对话、 使用无边记建立结构，并用“未学会 / 已学会”管理真实学习状态。

  • 中心设置管规则，区域小设置做单主题、单文章、单星系覆盖。
  • 文章步骤可关闭、重排和还原，不删除任何学习数据。
  • AI 问答自动带入当前文章、原文选区和已写批注。
  • 完成学习后状态自动同步到宇宙，不维护两套进度。
界面二 · 炼金宇宙

让长期积累变得可见、可进入、可探索

3D 宇宙不是装饰背景，而是用户知识状态的空间表达。 用户可以搜索知乎内容、进入主题星系、双击恒星调整星系、 在星球详情中继续学习或同步学习状态。

  • 每个星系由中心恒星和文章行星组成，位置采用三维错落布局。
  • 单击恒星进入星系，双击打开颜色、公转和星球增删设置。
  • 暗星与未学会文章同步，亮星与已学会文章同步。
  • 背景由三层常显星点组成，保持克制、稳定的沉浸氛围。

05 / 用户路径

从授权到回流，形成一个完整可演示的最小闭环

阶段 用户操作 产品反馈 价值结果
01 接入 授权知乎，或先体验系统推荐 收藏按主题组织，空收藏有明确空态 降低第一次使用门槛
02 炼化 选择一篇文章并完成学习步骤 生成结构化拆解、AI 追问和学习札记 从“看过”进入“能解释”
03 成形 完成学习并点亮星体 文章状态、列表状态和星球亮度同步 形成可持续积累的可视反馈
04 连接 建立概念关联和主题结构 图谱与宇宙形成知识链路 从碎片进入个人体系
05 输出 生成回答、笔记或表达材料 保留来源索引，一键回看知乎原文 从消费者走向创作者

06 / 整体技术实现

前端负责体验，后端保管能力，知乎保留内容主权

技术方案遵循一条清晰边界：浏览器只负责交互与状态表达， 所有密钥、长期凭证和敏感数据均由服务端管理。

BROWSER

体验与状态层

  • HTML / CSS / JavaScript 单页应用
  • React + TypeScript 重构验证
  • Three.js WebGL 三维宇宙
  • localStorage 本地状态与离线缓存
  • SSE 流式 AI、WebSocket 多人房间
→
NODE SERVICE

能力与安全边界

  • 零运行时依赖静态托管 + REST
  • 知乎 OAuth 回调与用户级收藏接口
  • DeepSeek / 知乎直答双通道模型代理
  • TTL 缓存、SSE、WebSocket 房间广播
  • JWT、SQLite、云端同步原型
→
ZHIHU + AI

内容与智能能力

  • 知乎开放平台搜索、热榜、回答
  • 用户授权后的收藏夹与收藏内容
  • 知乎直答负责知识问答
  • DeepSeek 负责抬杠与结构化拆解
  • 原文始终跳转知乎完整语境
01

内容模型

主题是知识星系，文章是行星。文章生命周期包含未学会和已学会两类核心状态， 已学会状态同时驱动文章界面、列表筛选和宇宙亮度。

02

状态模型

文章使用唯一 `learned` 状态作为真源。完成学习后自动点亮， 星球取消点亮会反向把文章同步为未学会，避免双状态漂移。

03

个性化模型

中心设置保存全局规则，区域小设置保存局部覆盖。 用户可调整学习步骤、拆解深度、AI 语气、主题排列和宇宙表现。

04

安全与版权

前端不持有知乎 token 或模型密钥；服务端使用最小授权。 产品保存索引、摘要和用户生成结构，不替代知乎原文。

07 / 与知乎社区生态的契合

不是把内容搬走，而是让知乎内容多活一次

炼知不建立封闭内容池，也不截流原创。它把用户已经收藏的知乎内容， 加工成用户能带走的理解，再把新的表达回流知乎。

内容侧

唤醒长尾内容

将被收藏后长期沉睡的高质量回答重新纳入学习、讨论和创作场景， 延长优质内容的价值周期。

用户侧

提高收藏完成度

通过拆解、追问、连接和输出，让收藏从“拥有内容”变成 “获得能力”，提高回访和长期留存。

创作者侧

降低二次创作门槛

学习结果保留来源索引，用户可以在理解的基础上形成回答草稿， 增加新的观点与经验，而不是简单洗稿。

平台侧

促进消费到创作的循环

用户从阅读者变成提问者、回答者和分享者， 让知乎的内容消费与内容生产形成更强的正反馈。

合规边界

官方授权、最小范围、来源可追溯

  • 只使用知乎开放平台官方 API 和用户明确授权的数据。
  • OAuth token 与模型密钥仅存服务端，前端永远看不到。
  • 默认保存收藏索引、摘要与用户生成结构，不替代原文全文。
  • 阅读与输出均保留来源，完整语境回到知乎查看。
  • AI 只做拆解、提问、反驳和整理，最终判断与发布仍由用户完成。

09 / 创作历程

每一次改版都来自一个真实问题

项目不是一次成型的，而是在“产品复杂度、操作清晰度、状态准确性和技术边界” 之间持续取舍、验证和重构。

09.10

先解决审美与信息秩序

收藏工具容易显得像普通清单。项目开始重做视觉、模块层级和首次使用说明， 让用户先理解“为什么学”，再操作“怎么学”。

结果：形成清晰的收藏拆解工作台。
09.11

从工作台升级为炼金宇宙

单纯列表无法表达长期积累。项目把主题映射为星系、文章映射为行星， 并加入炼金炉、关系链、昼夜、天气、原文批注和看山陪伴。

结果：学习进度第一次成为可探索的空间。
09.12

反思高耦合与操作复杂度

原有代码把所有功能压在少数超大文件中，且设置、步骤和宇宙操作过多。 随后拆出明确的视图、中心设置与区域小设置，并完成性能、覆盖层和移动端修正。

结果：功能保留，操作逻辑与视觉层级更稳定。
09.13

接入真实知乎数据与 AI 能力

v7 接入知乎开放平台、DeepSeek/知乎直答双通道、多人实时房间、 原文查询与批注。另一条 v8 支线验证了账户、云端同步、炼金配方和无限白板。

结果：从静态 Demo 变成可真实运行的知识服务原型。
09.14

重新审视知识的最小单位

React 重构版把文章进一步拆为知识卡、概念、项目、连接和输出， 并解决本地双击打开、原文入口和自动拆解问题。 当前宇宙版则继续完善登录推荐态、真实收藏态和文章-星球状态同步。

结果：产品从“文章管理”走向“个人知识网络”。

10 / 关键问题与解法

把开发过程中踩过的坑，沉淀成产品规则

发现问题 背后的思考 最终处理
收藏很多，却没有下一步 缺的不是分类，而是加工动作 建立选料、拆解、抬杠、图谱、回流闭环
功能过多，用户不知道怎么用 入口不能等于能力，必须按意图组织 固定操作导引、中心设置与区域小设置
文章已学会，星球却没有点亮 两个状态描述同一件事，容易漂移 使用单一 `learned` 状态，文章和宇宙双向同步
3D 宇宙好看但方向混乱 沉浸感不能牺牲可理解性 正向拖动、先定位后缩放、近距显示文章名
本地双击网页出现空白 浏览器会阻止 file:// 下的模块与绝对路径资源 单文件构建产物 + Hash 路由 + 本地入口跳转
知乎授权尚未完全开放 不能把未来能力伪装成已经可用 未登录展示推荐，授权后切真实收藏，空收藏明确显示为空
